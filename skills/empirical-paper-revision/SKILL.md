# 实验类论文审稿意见响应与修订

## 第一性原则：先分类，再动手

- **文字类**（收缩结论、删夸大表述）→ 直接改，但等数据类重跑完再一次性改，避免数字改两遍
- **数据类**（公平性、计时口径、统计可靠性、资源证据）→ 必须重跑实验，没数据前不动正文

## 审稿人最常打、必须实测补的点（检查清单）

1. **结论外推**：单数据集结论禁止推广到语言/领域层面；硬件是固定条件不是自变量
2. **比较公平性**：输入范围不一致（如 128 token 截断 vs TF-IDF 全文）→ 报告截断率 + 加同输入对照组
3. **计时口径统一**：特征构建/分类器训练/编码/单请求端到端延迟 四口径分开；批量平均耗时≠单请求延迟（实测差距可从"数量级"缩水到几十倍）
4. **统计可靠性**：多种子(3-5) + 配对 bootstrap 95% CI + McNemar 精确检验 + 逐样本预测存档 npz
5. **资源画像**：`resource.getrusage` 峰值 RSS + 独立线程每 2s 采样 /proc/meminfo swap + loadavg
6. **诚实边界**：一次 OOM ≠ "必然不可行"；未尝试的实验写"按预估排除"而非"实测失败"
7. **消融意识**：[CLS] vs mean pooling 这类顺手可加的对照，审稿人一定会要

## 复用技巧：embedding 缓存

多划分种子的 Transformer 实验：**全语料编码一次缓存 npy**，各种子只做索引切片+重训分类器，多小时压到分钟级。

## 交付纪律

- 数字以 results.json 为准，论文表格逐字转录，附"以 json 为准"声明
- 中英文双版数字逐一核对（可派子代理翻译后程序化校验关键数值）
- 修订后"矛盾自检"：正文每个数字 grep 对照 results.json
