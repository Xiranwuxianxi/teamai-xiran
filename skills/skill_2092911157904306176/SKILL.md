# 妙想自选管理

通过脚本查询与管理用户在 **Choice「我的自选」** 与 **东方财富 App** 的自选列表。适用场景包括：
- **查看全部自选列表（CSV）**
- **自选选股：在自选范围内按条件筛选**（如「我的自选中股价大于20的」）
- **将 A 股 / 港股 / 美股加入 Choice 自选**
- **将 A 股 / 港股 / 美股从 Choice 自选移出**

所有真实业务逻辑封装在 `{baseDir}/scripts/manage_watchlist.py`。本文件说明：如何判断意图与业务线、如何调用脚本、如何把脚本输出转给用户。

## 密钥来源与安全说明

- 本技能依赖 `EM_API_KEY`。优先从平台私有跨会话缓存读取并注入当前 `scripts/manage_watchlist.py` 进程；平台凭据不可读、缺失或失效时，再复用本机私有缓存 `~/.mx-skills/em_api_key`；两级缓存都不可用时，才调用东方财富妙想 MCP 的 `mx_get_user_api_key` 获取当前用户 API Key。
- **没有已缓存 Key 时仍然要调用本技能**：不要因环境变量未配置而跳过；若东方财富妙想 MCP 不可用或未返回有效 `apiKey`，直接跑脚本，由脚本输出 `need_auth` + `authUrl` 授权链接。
- 自选业务接口需要 Key 已完成扫码绑定（ctoken/utoken）。若 Key 可用但未绑定通行证，脚本会输出新的 `authUrl`，按重新扫码绑定处理。
- 禁止在代码、提示词、日志或输出文件中硬编码/明文暴露密钥。

## 功能范围

### 核心能力
- **市场范围**：
  - **查询**：原样返回 `search-code` 接口结果
  - **Choice 新增 / 删除**：仅支持 A 股、港股、美股
- 查询支持两类：
  - **全部自选**：导出当前业务线自选列表
  - **自选选股**：把带条件的自然语言问句交给查询接口筛选（如股价、涨跌幅等条件）
- 按业务线查询自选列表，有数据时导出 CSV（名称、代码、市场代码、最新价（元）、涨跌幅（%）；代码按文本写入，避免 Excel 丢掉前导 0）
- Choice 业务线（含默认的「其他」）：实体识别后新增 / 删除 Choice「我的自选」（A/港/美）
- 东方财富业务线：仅支持查询；新增 / 删除返回固定兜底话术
- 未授权、Key 失效或未绑定通行证时：输出 `need_auth` + `authUrl`，由 Agent 把 `authUrl` **原样发给用户**（可点击链接），引导用户打开链接后扫码绑定，再发原指令。**不要**自行绘制或展示二维码。

### 触发规则（何时使用本技能）

**硬触发信号：问句中明确出现「自选 / 自选股 / 我的自选」。** 没说「自选」不要调用本技能。

常见表达：

- 查询：「我的自选有哪些」「看一下我的自选列表」「导出我的自选」「东财 app 里的自选」
- 自选选股：「我的自选中股价大于20的」「自选里涨幅前5」「choice自选中市值超过100亿的」
- 新增：「把贵州茅台加到自选」「帮我把 600519 加自选」「把腾讯控股加自选」
- 删除：「从自选里删掉中兴通讯」「把 000063 移出自选」「这些从自选去掉」

上下文已明确在谈自选（例如上一轮用户刚确认「加到自选」），后续用「这几只 / 这些 / 刚才那些」继续加减或查看时，也应触发；调用前先做指代消解。

### 模糊表达：先问，不要直接触发

用户只说「关注 / 观察 / 收藏 / 盯一下 / 加入观察」等、**未出现「自选」**时：

- **不要**调用本技能
- 先引导确认，例如：「是要把 XX 加到自选里，方便后续观察吗？」
- 用户明确说「要 / 加自选 / 看自选」之后，再调用本技能

### 不触发规则（何时不要使用本技能）
- 问句中**未出现「自选」**，仅有「关注、观察、收藏、盯盘」等模糊说法（先反问，见上）
- 用户只是查询行情、估值、财报等公开数据（应走金融数据类技能）
- 用户做个股/基金综合诊断（应走诊股/诊基技能）
- 用户要求**全市场**选股筛选、且问句**未限定在「我的自选」范围内**（应走选股技能）

## 业务线识别

调用脚本前，从用户问句识别**业务线**，作为 `--business-line`：

| 业务线 | business-line | 触发关键词 | 实际走哪条链路 |
| --- | --- | --- | --- |
| 东方财富 | `eastmoney` | 「东财 app」「东方财富」「东财」「东财客户端」等 | 东财 App 自选 |
| Choice | `choice` | 「choice」「Choice 终端」「choice 金融终端」等 | Choice「我的自选」 |
| 其他（默认） | `other` | 用户**没有**明确提及业务线 | **等同 Choice**（默认走 Choice「我的自选」） |

判断规则：
- 用户明确说东财 → 传 `eastmoney`
- 用户明确说 choice → 传 `choice`
- 两者都没说 → 传 `other`（**脚本内部按 Choice 处理，不要猜成东财**）

## 三类操作的判定

| 意图 | operation | 典型关键词 |
| --- | --- | --- |
| 查询自选（全部或条件筛选） | `query` | 看、查、列、有哪些、列表、导出；以及「自选中…大于/小于/前N」等筛选 |
| 新增自选 | `add` | 加、加入、添加（问句已明确「自选」的前提下） |
| 删除自选 | `delete` | 删、删除、移除、移出、去掉（问句已明确「自选」的前提下） |

如果一句话里既有「加」又有「删」，拆成两次调用，先删后加。

### 脚本内部处理路径（仅供理解，勿自行重实现）

| 操作 | 东方财富 (`eastmoney`) | Choice（`choice`）/ 其他默认（`other`→Choice） |
| --- | --- | --- |
| `query` | 查东财 App 自选（原样返回接口全部标的）；支持全部 / 条件筛选；CSV 底部备注见下 | 查 Choice【我的自选】（原样返回接口全部标的）；支持全部 / 条件筛选；CSV 底部备注见下 |
| `add` | 兜底：`暂时不支持新增东财app自选股` | **必须先**走实体识别 SaaS → 仅 A/港/美可调新增接口 |
| `delete` | 兜底：`暂时不支持删除东财app自选股` | **必须先**走实体识别 SaaS → 仅 A/港/美可调删除接口 |

**查询硬规则：**

1. `--user-query` **原样**作为查询接口 `keyWord` 透传（脚本不做归一、不改写）
2. 全部自选、自选选股都由 Agent 把完整自然语言写进 `--user-query`，例如 `我的自选` / `我的自选中股价大于20的`
3. **禁止**先全量导出再在本地自己筛；条件筛选应交接口处理
4. 结果为空：
   - 东财 → `您的东方财富app自选列表暂无证券，通过对话直接添加吧`
   - Choice（含 `other`）→ `您的choice自选列表暂无证券，通过对话直接添加吧`

**新增 / 删除硬规则（脚本已实现，Agent 不要绕过）：**

1. 用户 `--user-query`（名称、简称、代码等自然语言）一律先调用实体识别 SaaS：`POST /proxy/entity/saas`，请求体为 `{"content":"<user-query>","typeCodes":"002001,002002,002003,002004","disamb":false}`（只识别 A/港/美股票）
2. 从识别结果的 `secuCode` + `marketChar` 拼出 Choice 实体代码（如 `300059.SZ`、`00700.HK`、`MU.O`）
3. 识别结果有 Choice 实体代码则原样调用新增 / 删除；识别为空（如转基因板块）→ 加自选返回 `该实体类型暂不支持加自选`，删除返回 `该实体类型暂不支持删除自选`
4. 将该实体代码作为 `sc` 传给 `add-self-select` / `delete-self-select`
5. **禁止**把用户原文直接当 `sc`；**禁止**跳过实体识别自行拼码
6. **不要**在本地按市场后缀过滤；是否可加减以实体识别结果为准

查询成功时 CSV 底部备注：

- 东财：`数据来源于东方财富，当前仅支持查询东财app的沪深京自选股`
- Choice（含 `other` 默认）：`数据来源于choice，查询仅支持【我的自选】分类下的A股（加减自选支持A/港/美）`

## 多轮上下文：指代必须先消解

脚本内部的实体识别接口只看 `--user-query`，**看不到对话上下文**。调用前必须先做指代消解，把「这几只 / 这些 / 刚才那些」展开成具体证券名称或代码。

| 用户原话 | ❌ 错误传参 | ✅ 正确传参 |
| --- | --- | --- |
| 「把这几只加自选」 | `--user-query "把这几只加自选"` | `--user-query "把贵州茅台、五粮液、泸州老窖加自选"` |
| 「刚才那只删掉」 | `--user-query "刚才那只删掉"` | `--user-query "把宁德时代从自选删掉"` |

若上下文没有可消解的明确证券，直接问用户具体想加 / 删哪几只。

## 前提条件

### 授权（已内联，无需单独跑）

本 Skill 依赖 `EM_API_KEY`。优先复用已缓存凭据：先从平台私有的跨会话持久存储读取 `EM_API_KEY`，可用时仅将其注入当前业务脚本进程并直接执行，不要重复调用 `mx_get_user_api_key`。若平台私有存储不可读、未提供或没有凭据，再安全检查本机私有缓存 `~/.mx-skills/em_api_key`（只能检查是否存在、长度是否大于 0，不能 `cat` 或打印真实值）；若存在有效凭据，直接运行本 Skill 的业务脚本，脚本会自动读取该文件。

仅当平台私有存储与本机缓存都缺失或已确认失效时，才调用东方财富妙想 MCP 的 `mx_get_user_api_key` 工具获取当前 OAuth2 登录用户的东方财富 API Key。若成功取得 `apiKey`，优先保存为平台私有的跨会话 `EM_API_KEY`；同时必须把完整值写入 `~/.mx-skills/em_api_key`，作为本 Skill 业务脚本可直接读取的本机私有缓存（权限尽量设为仅当前用户可读写）。随后仅注入当前业务脚本进程并直接执行本 Skill 的业务脚本，不要再触发 skill 层面的二次授权、扫码授权或 `auth.py ensure`。

仅当 `mx_get_user_api_key` 不可用、调用失败、未返回有效 `apiKey`，或当前运行环境没有可用的东方财富妙想 MCP 时，才回退到 skill 内置授权流程。内置授权检查已内联到业务脚本，**直接执行业务脚本，不要先单独运行 `auth.py ensure`**，也不要把内置授权做成默认独立前置步骤；不要因为环境里没有 `EM_API_KEY` 就跳过本 Skill。回退时脚本按 `EM_API_KEY` 环境变量、`~/.mx-skills/em_api_key` 文件的顺序读取凭据，不再使用内置兜底 key。

处理 `apiKey` 时不要把真实值输出到 stdout/stderr、日志、命令回显或对话正文中；不要使用 `echo`、`cat`、`env | grep`、或把真实 key 直接拼进 shell 命令行的方式检查或传递凭据。需要确认凭据存在时，只检查文件是否存在、长度是否大于 0、或输出脱敏后的前后缀。执行查询或生成任务时优先使用平台私有存储注入当前业务脚本进程；没有平台凭据时，再让脚本从 `~/.mx-skills/em_api_key` 读取。确需进程级注入时，使用工具/运行时的环境变量能力，不要把真实 key 写进 shell 命令字符串。

| 退出码 | 含义 | agent 动作 |
| --- | --- | --- |
| `0` | 成功 | 按下方「输出规范」转述脚本 stdout |
| `10` | 需用户授权 / 绑定通行证 | 按 `need_auth` 流程处理：把 `authUrl` **原样发给用户**，请用户点开链接扫码|
| `2` | 业务/接口错误，或 argparse 缺必填参数 | **先看 stdout/stderr**：有 `Error:` 则转述错误；有 usage / 缺参提示则补全参数后重跑。不要按「退出码 1」理解参数错误。网络类失败最多重试 1 次 |

脚本不会使用退出码 `1`。判断时以 stdout 为准：`need_auth: true` → 扫码；`Error:` → 失败；其余成功输出按输出规范转述。

退出码 `10` 时 stdout 会打印：

```text
need_auth: true
authUrl: <以实际返回为准>
apiKeyUrl: <以实际返回为准>
尚未完成授权或未绑定通行证。请打开授权链接扫码绑定，完成后重新发送原指令。
```

Agent 必须：

1. **把 `authUrl` 原样发给用户**，请用户点开链接，用东方财富/妙想 App 扫码绑定通行证；**不要**自行绘制或展示二维码
2. 无法打开 `authUrl` 时再提供 `apiKeyUrl` 作为手动获取 Key 的备选
3. **不要轮询、等待或询问是否扫完**；提示用户完成后重新发送原指令
4. 不得向用户展示、复述 `apiKey` / `EM_API_KEY`

接口返回 `code=401` 且 `message=未获取到用户 ct/ut，请先绑定通行证` 时，脚本同样走上述扫码流程（清理失效凭据并生成新的 `authUrl`），不要改口成「去官网注册」。

授权、凭据持久化及 401 失效处理必须遵循 [授权协议](references/auth_protocol.md)。

### 配置 Token（可选）

平台私有跨会话存储已有 `EM_API_KEY` 时，调用前由运行环境注入当前 `scripts/manage_watchlist.py` 进程即可；不要把真实 key 写进用户可见命令、日志或对话正文。仅在本地调试且确认不会回显真实值时，才使用进程级环境变量。

### 运行时配置

运行脚本时，除 `EM_API_KEY` 外，还必须确保 `EM_BASE_URL`、`OPEN_ID_VENDOR`、`OPEN_ID_APP`、`EM_AUTH_BASE`、`AUTH_API_KEY_URL` 已由环境变量注入，或在 Skill 打包/安装阶段完成占位符替换。其中 `EM_BASE_URL` 用于自选查询、新增、删除和实体识别接口；`EM_AUTH_BASE`、`AUTH_API_KEY_URL` 用于脚本内置链接授权兜底流程。

若这些配置仍为 `__...__` 占位符，agent 不应改用其他 MCP 查询或选股工具替代本 Skill 输出，而应报告运行时配置缺失。

## 快速开始

```bash
python3 {baseDir}/scripts/manage_watchlist.py \
  --user-query "<指代已消解的明确问句>" \
  --operation query|add|delete \
  --business-line eastmoney|choice|other
```

**参数说明：**

| 参数 | 说明 | 必填 |
| --- | --- | --- |
| `--user-query` | 指代消解后的明确文本；query 可带筛选条件；add/delete 必须包含明确证券 | ✅ |
| `--operation` | `query` / `add` / `delete` | ✅ |
| `--business-line` | `eastmoney` / `choice` / `other`；未指明业务线时传 `other`（默认按 Choice） | ✅ |

## 输出规范

拿到脚本 stdout 后，**对用户的可见回复必须以脚本输出为依据**，原样转述业务话术，禁止编造「已添加成功」或二次调接口「确认」。

| 脚本输出 | 你应该做的 |
| --- | --- |
| `need_auth: true` + `authUrl:` + `apiKeyUrl:` | **把 `authUrl` 原样发给用户**，请用户点开链接扫码绑定；不要画二维码。无法打开链接时再给 `apiKeyUrl`。不要轮询，提示完成后重发原指令。不要向用户展示 apiKey |
| `您的东方财富app自选列表暂无证券，通过对话直接添加吧` | **原样**转给用户 |
| `您的choice自选列表暂无证券，通过对话直接添加吧` | **原样**转给用户 |
| `暂时不支持新增东财app自选股` / `暂时不支持删除东财app自选股` | **原样**转给用户；可建议改走 Choice 自选 |
| `已成功添加到 choice--我的自选分类下：…；已在自选：…；自选添加失败：…` | **原样**转给用户。新增按实体返回：成功 / 已在自选 / 失败可能同时出现；「重复添加」类接口文案已产品化为「已在自选」，不要改写成「全部失败」 |
| `【我的自选】数量已达到10000上限` | **原样**转给用户 |
| `已成功删除 choice--我的自选 分类下对应证券：…；自选删除失败：…（自选股不存在）` | **原样**转给用户。删除按实体返回，成功/失败可能同时出现（接口可能是「部分成功」）；「成分不存在」已产品化为「自选股不存在」，不要改写成「全部失败」 |
| `该实体类型暂不支持加自选` / `该实体类型暂不支持删除自选` | **原样**转给用户（实体识别为空，如板块等） |
| `Saved: ...csv` + 列表摘要 | 告知用户已导出，并给出文件路径；可基于 CSV/摘要做轻度说明，勿捏造未返回字段 |
| `Error: ...` | 告知服务异常，不要编造自选结果 |

## 边界与注意事项

1. **必须明确「自选」才调用**：只说「关注 / 观察 / 收藏」时先询问是否加自选，不要直接调脚本。
2. **查询原样返回，加减跟实体识别走**：查询不做本地市场过滤；Choice 新增/删除以实体识别结果为准，不在本地卡市场后缀。识别为空则返回「该实体类型暂不支持加/删除自选」。
3. **实体识别在脚本内部**：不要自己用正则抽代码；把消解后的中文问句完整传给脚本。
4. **业务线判断只看用户原话**：用户不说就是 `other`，脚本默认按 **Choice** 处理。
5. **查询问句原样透传**：`--user-query` 直接作为接口 `keyWord`（含全部自选 / 自选选股条件），不要依赖脚本改写，也不要先全量导出再本地筛选。
6. **东财 App 限制不要绕过**：即使用户坚持「就要在东财里加茅台」，也只能复述不支持话术。
7. **不要替脚本补业务判断**：不要再做实体识别、不要二次查询确认是否添加成功。

## 常见问题

**退出码 10 / `need_auth: true`**  
→ 未授权或未绑定通行证。把 `authUrl` 原样发给用户，请其点开链接扫码绑定；完成后让用户重新发送原指令。不要画二维码，不要轮询。

**自选添加/删除失败含「验证用户信息失败」**  
→ 脚本会改走 `need_auth`：清理失效 Key 并输出新的 `authUrl`。Agent 把链接发给用户重新扫码绑定，完成后重发原指令；不要只复述「验证用户信息失败」而不给解决办法。

**接口 `code=401`，`message=未获取到用户 ct/ut，请先绑定通行证`**  
→ 与上相同：脚本会忽略失效的环境变量/文件 Key，直接生成授权链接。Agent 必须把链接发给用户，不要改成「去官网注册」，也不要让用户手动删除环境变量。Agent 仍应从跨会话持久存储删除失效凭据，避免下次再注入旧 Key。

**错误：EM_API_KEY 读取/落盘异常**
→ 若走平台私有缓存/MCP 路径，确认运行环境是否已把 `EM_API_KEY` 注入当前脚本进程；若走 skill 内置授权回退路径，再按脚本提示检查 `~/.mx-skills/em_api_key` 后重试。
