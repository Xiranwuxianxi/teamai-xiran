# 火灵进度汇报模板

每轮 assistant 回复**开头**必须使用此结构。先进度块，后正文。

## 标准格式

```markdown
---
火灵 ████████░░░░░░░░░░ 42% | 剩余 58% | 阶段: 实现 | 置信度: 中
当前: 编写认证路由 | 已完成: 2/7 里程碑 | ETA: ~15min
---

| 里程碑 | 权重 | 状态 | 验证证据 |
|--------|------|------|----------|
| 需求确认 | 5% | done | 验收标准已列出 |
| 环境检查 | 5% | done | `node -v` v20.x, `npm -v` 10.x |
| API 路由 | 20% | doing | — |
| 错误处理 | 10% | pending | — |
| 单元测试 | 20% | pending | — |
| 集成测试 | 15% | pending | — |
| 端到端验证 | 15% | pending | — |
| 文档 | 10% | pending | — |

[正文：本步做了什么、下一步是什么]
```

## 字段说明

| 字段 | 必填 | 说明 |
|------|------|------|
| 进度条 | 是 | 20 格，`█` 已完、`░` 未完 |
| 完成% | 是 | 加权里程碑计算 |
| 剩余% | 是 | 100 - 完成% |
| 阶段 | 是 | 规划 / 实现 / 测试 / 部署 / 收尾 |
| 置信度 | 是 | 高 / 中 / 低 |
| 当前 | 是 | 正在执行的里程碑名称 |
| 已完成 | 是 | done 数 / 总里程碑数 |
| ETA | 是 | 预估剩余时间，首轮可写「待估」 |

## 进度条生成

```
filled = round(完成% / 5)   # 0–20
bar = "█" * filled + "░" * (20 - filled)
```

示例：

| 完成% | 进度条 |
|-------|--------|
| 0% | `░░░░░░░░░░░░░░░░░░░░` |
| 25% | `█████░░░░░░░░░░░░░░░` |
| 50% | `██████████░░░░░░░░░░` |
| 100% | `████████████████████` |

## 状态变更附注

重试、阻塞、进度调整时在表后追加一行：

```markdown
> 重试: API 路由 第 2 次 — 修正路由路径后待验证
> BLOCKED: 需要 DATABASE_URL 环境变量
> 进度调整: +1 项 (部署验证)，完成% 从 70% → 63%
> ⚡ 打断决策: SUSPEND | 原任务挂起，优先新需求
> 原任务: 实现 REST API (35% 已完成，3 项 suspended)
> 新需求: 修复登录页样式 bug
> 理由: 新需求更紧急，用户未要求放弃 API 工作
```

## 打断决策块（用户中途新需求时强制）

第一轮回复在进度块**之前**输出：

```markdown
> ⚡ 打断决策: SUSPEND | 原任务挂起，优先新需求
> 原任务: 实现 REST API (35% 已完成)
> 新需求: 修复登录页样式
> 理由: 用户说「先做登录页」，未否定原 API 任务
```

决策代号：`CONTINUE` | `PARALLEL` | `SUSPEND` | `MERGE` | `ABORT`

| 代号 | 进度块阶段字段 |
|------|----------------|
| CONTINUE | 原阶段不变 |
| PARALLEL | `阶段: 并行` |
| SUSPEND | `阶段: 新需求优先` |
| MERGE | `阶段: 范围调整` |
| ABORT | `阶段: 任务切换` |

打断后里程碑表须体现 `suspended` / `cancelled` 状态。

## 禁止

- 仅写「进行中」无进度条与百分比
- 用「第 N 次循环」代替完成%
- 无里程碑表的空泛状态更新
