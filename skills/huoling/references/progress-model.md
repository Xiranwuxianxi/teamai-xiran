# 火灵进度估算模型

进度由**加权里程碑**驱动，不用循环次数。

## 核心公式

```
完成% = round( Σ(已完成里程碑权重) / Σ(全部里程碑权重) × 100 )
剩余% = 100 - 完成%
```

进度条填充格数（固定 20 格）：

```
filled = round(完成% / 5)
bar = "█" * filled + "░" * (20 - filled)
```

## 里程碑权重参考

| 类型 | 建议权重 | 说明 |
|------|----------|------|
| 需求澄清 / 方案确认 | 5–10% | 明确目标与验收标准 |
| 环境 / 依赖准备 | 5–10% | 工具链、依赖安装验证 |
| 实现子模块 | 10–25% / 项 | 按复杂度分配，简单 10%，复杂 25% |
| 集成联调 | 10–15% | 模块间接口验证 |
| 测试与验证 | 15–20% | 单元/集成/E2E |
| 文档 / 收尾 | 5–10% | README、部署说明等 |

**约束**：所有里程碑权重之和必须为 100%。

## 状态定义

| 状态 | 含义 |
|------|------|
| `pending` | 未开始 |
| `doing` | 进行中（同时仅 1 个） |
| `done` | 完成且有验证证据 |
| `failed` | 失败，附原因与重试计划 |
| `blocked` | 真阻塞，需外部输入 |
| `suspended` | 原任务挂起，待恢复（用户打断后） |
| `cancelled` | 用户确认放弃或被 MERGE/ABORT 替代 |

## 打断后的进度重算

存在 `cancelled` 或 `suspended` 时：

```
有效权重 = Σ(非 cancelled 里程碑权重)
完成% = round( Σ(done 权重) / 有效权重 × 100 )
剩余% = 100 - 完成%
```

- `suspended` 计入有效权重（恢复后继续）
- `cancelled` 从有效权重剔除

详见 [interrupt-handling.md](interrupt-handling.md)。

## 置信度

根据信息完整度标注 ETA 置信度：

| 置信度 | 条件 |
|--------|------|
| 高 | 里程碑明确、无未知依赖、类似任务经验 |
| 中 | 部分未知、可能发现子任务 |
| 低 | 大量未知、依赖外部系统、首次接触领域 |

## 动态重估规则

1. **新增里程碑**：从当前进行中项拆分或发现遗漏时，加入表并重新分配权重（保持总和 100%）。
2. **权重调整**：复杂度超预期时，从低优先级项挪权重给阻塞项。
3. **汇报格式**：`进度调整: +2 项 (集成测试、部署验证)，完成% 从 45% → 38%`
4. **禁止**：用 `第 3/10 次尝试` 或 `循环 5 次` 作为主进度。重试次数仅可作为里程碑表下的附注。

## 示例：REST API 任务分解

| 里程碑 | 权重 |
|--------|------|
| 需求与验收标准 | 5% |
| 项目脚手架 | 10% |
| 数据模型 | 15% |
| CRUD 路由 | 25% |
| 错误处理 | 10% |
| 单元测试 | 20% |
| 端到端验证 | 15% |
| **合计** | **100%** |

完成「项目脚手架」(10%) 且验证 `npm test` 可运行后：完成% = 10%，剩余% = 90%。

## ETA 估算

```
ETA ≈ (剩余权重 / 已完成权重) × 已用时间   (至少完成 1 项后)
```

首轮可写 `ETA: 待估` 或基于类似任务的经验区间。
