# 指数信息查询

把中文自然语言中的指数查询请求，转成真实数据查询，并以普通投资者能理解的方式返回事实信息和比较结果。

## 免责声明

本技能仅提供基金和指数相关数据查询服务；基于查询结果生成的归纳、比较和说明由 AI 自动生成，仅供参考，不构成投资建议、收益预测或任何交易决策依据。

## 产品说明

指数直通车 AI Skills 是易方达基金专为 AI 智能体打造的指数产品数据查询工具。它致力于搭建大模型与指数基金市场之间的信息桥梁，助力各类智能体实时调取准确、齐全的场内 ETF 与场外指数基金产品数据，全面覆盖指数基金检索、持仓分析、分红追踪等核心应用场景，显著提升指数投资的数据获取与分析效率。


每位用户每日享有 500 次免费 API 接口调用额度。单次提问可能调用多个接口，额度按实际接口调用次数计算。

如需获取API Key，请在微信搜索“指数直通车”小程序，在「AI Skills」页面申请。更多说明可访问帮助文档：https://cdn.efunds.com.cn/eda/h5/itcenter/pd/ai-skills-doc/help.pdf

问题反馈或技术支持邮箱：indexhub@efunds.com.cn

## When To Use

用户表达以下意图时，使用本 skill：

| 场景 | 典型请求 |
|---|---|
| 指数基础信息 | 查询某只指数的名称、分类、发布时间、基日、编制机构 |
| 指数筛选与比较 | 按分类、表现、估值、基本面或跟踪产品条件筛选指数，并比较风险收益指标 |
| 成分股查询 | 查询指数前十大成分股，或按一只或多只股票反查相关指数 |
| 行业与市值分布 | 查询指数的行业权重、大中小盘数量和占比 |
| 收益与风险 | 查询区间收益、年化收益、波动率、最大回撤或夏普比率 |
| 估值与基本面 | 查询PE、PB、PS、历史分位、ROE、股息率、营收或利润增速 |
| 相关基金 | 查询跟踪指数的ETF、场外基金、数量和规模 |
| 实时行情 | 查询最新点位、涨跌额/幅、成交量/额或分钟走势 |

## What This Skill Is Not

- 不提供买卖建议、收益承诺或替代投资顾问服务
- 不执行开户、下单、申购、赎回或任何账户操作
- 不基于未经查询的数据作答；数据不可用、无权限或无匹配结果时，应明确说明限制
- 不把指数点位当基金净值，不把指数收益或成分股当作跟踪基金的实际收益或持仓
- 不覆盖具体ETF或场外基金的产品比较；此类问题应转向 `etf-fund-query` 或 `open-fund-query`

## 对象识别与路由

- 查询前先区分指数、ETF 和场外指数基金。三者都可能使用6位代码，不能只凭代码格式判断类型，应结合名称、用户用词和上下文识别。
- 指数是市场基准，回答的是指数点位、指数收益、成分股和估值等；ETF 和场外指数基金是跟踪指数的基金产品，基金的价格、净值、收益和持仓不能用指数数据代替。
- ETF 在交易所上市，使用盘中价格、成交额、IOPV 和溢折率等口径；场外指数基金按净值成交，没有盘中价格和盘口。
- 用户只说指数全称或简称，如“沪深300”“中证500”，且没有提到 ETF、基金或具体基金代码时，查询指数本身，不从相关基金中任意选择一只代替；仍有歧义时再请用户确认。
- 用户已明确对象类型时，直接使用对应的 skill。问题同时包含指数和基金时分别查询并清楚标注，不先把代码送入错误接口试探。

## Execution Workflow

处理用户问题时，按以下步骤执行：

1. **识别查询对象**
   - 识别6位指数代码、指数名称、分类、行业主题、成分股、筛选条件或时间区间。
   - 用户只给名称、主题或复杂条件时，先搜索候选指数，再基于返回结果继续查询详情。

2. **选择查询能力**
   - 根据问题意图选择搜索、成分股反查、详情、持仓、收益、估值、基本面、盘口行情或分钟行情。
   - 具体接口、字段路径、单位换算、日期口径和行情接口选择以 `references/catalog-index.md` 为准。

3. **调用真实数据**
   - 所有数据访问必须经由本 skill 的 `scripts/api_client.py` 发起；它是唯一的鉴权、缓存和调用记账通道。
   - 禁止自行使用 curl、requests、urllib、fetch 或自编脚本直接请求数据服务；禁止把 `config.py` 当作模块 import 后自行发请求。
   - 不凭记忆补数据；不使用外部网页替代 skill 数据。

4. **组织回答**
   - 先给一句话结论或比较框架，再列关键数据。
   - 多指数比较时说明筛选或排序依据。
   - 只展示与用户问题相关的核心指标，默认控制在3-5项。

5. **输出前检查**
   - 最终回答必须通过本 skill 的回答检查工具处理。
   - 不展示原始响应、内部字段路径、鉴权信息、异常占位值或调试日志。

## 安装说明

- 若你单独获取并安装本 skill，请查看同目录下的 `INSTALL.md`，按其中步骤完成安装与授权配置。
- 若你使用的是 Index Hub 组合包，请优先使用组合包根目录下的 `install/install.sh` 进行统一安装。

## Runtime And Access

- 数据查询通过本 skill 随附的本地配置完成。使用前应确保已按安装说明完成授权配置。
- 运行时可用 `INDEX_HUB_API_KEY` 临时覆盖授权信息；默认从 `~/.config/index-hub/api_key` 读取，且兼容旧变量 `ETF_API_KEY`。如均未配置，应按安装流程引导用户完成配置和验证。
- 回答用户时只展示查询结论和必要口径，不展示配置文件内容、鉴权信息、服务地址、原始请求或原始响应。
- 如果授权不可用、服务不可达或返回无权限，应明确说明当前无法查询，并提示用户检查配置或权限。

## Answer Validation

- 每次对用户输出最终答案前，都应使用 `guardrails.py` 中的最终回答检查能力。
- 若检查未通过，应改写答案后重新检查；不要把未通过的内容直接展示给用户。
- 在组织答案前，先把接口中的缺失值、`None`、`null` 和异常占位值转换成自然语言；最终回答检查不能替代数据解析层的清洗。
- 该检查用于统一免责声明、阻止真实凭据和内部服务地址泄露、拦截异常哨兵值，并降低不当投资表达风险；说明性的配置名称和空值术语可以正常出现。

## Query Capabilities

| 能力 | 用途 |
|---|---|
| 指数搜索（`search/chinaIndex`） | 按代码、名称关键词检索境内指数，并用 `filters` 按分类、表现、估值、基本面、跟踪产品等服务端筛选，随附 `lastPrice`、`changeRate` 行情字段 |
| 成分股反查指数（`search/index-by-stock`） | 根据一只或多只股票查找包含这些股票的指数；只返回指数列表与成分占比，不含跟踪产品——需要跟踪 ETF/场外基金时，用返回的指数代码再调 `search/chinaIndex` 或 `index/detail` 读取 `relatedETF`/`relatedOutIndex` |
| 批量指数详情（`index/detail`） | 查询分类、编制属性、风险收益、行业和市值分布、相关基金、代表产品等 |
| 批量指数持仓（`index/holdings`） | 查询前十大成分股和权重 |
| 批量区间收益（`index/return`） | 查询预设周期或自定义区间收益 |
| 批量指数估值（`index/valuation`） | 查询PE、PB、PS、PCF-TTM当前倍数和历史分位 |
| 批量基本面指标（`index/financial-indicators`） | 查询ROE、股息率、营收和利润增速 |
| 指数盘口行情（`quote/index`） | 批量查询最新点位、涨跌额/幅、成交量/额和精确行情时间，单次最多 50 只 |
| 指数历史K线（`quote/index/kline`） | 查询日/周/月/分钟历史K线 |
| 指数分钟行情（`quote/minite`） | 批量查询当日分时分钟走势，或按 `lastTimestamp` 获取增量分钟数据，并随附最新盘口快照 |
| 热搜榜（`discovery/hot-search`） | 查询指数直通车产品内部搜索热榜关键词 |
| 按类型热搜推荐（`discovery/hot-search-recommend`） | 按产品类型（指数/ETF/场外基金）查询热搜推荐列表 |

具体请求参数、响应路径、字段名、单位和异常值处理规则，必须以 `references/catalog-index.md` 为准。

## Query Rules

- 同一问题包含多个意图时，按“搜索/识别标的 → 详情 → 持仓/收益/估值/基本面/行情 → 解释与风险提示”的顺序处理。
- 筛选类条件（表现、估值、基本面、跟踪产品区间）必须优先用 `search/chinaIndex` 的 `filters` 参数在服务端完成，禁止靠翻页逐条人工过滤。搜索响应已随附行情、表现、估值基本面和跟踪产品等字段；筛选、排序和比较基于搜索结果在本地完成，不为每只候选重复请求详情。`pageSize` 取大值一次取回候选，以 `totalNum` 为界，仅当前几页确实无匹配时才翻页，最多翻页 5 页，仍覆盖不全时在回答中说明筛选条件、覆盖范围与排序口径，不得继续扫库；多指数详情用批量接口一次传入全部代码，禁止逐个单查。
- 指数检索固定使用 `search/chinaIndex`，不执行路径回退；该接口只覆盖境内指数，用户询问境外指数时如实说明当前仅支持境内指数查询。
- 搜索只用于发现与筛选；用户已给明确代码且问单项指标时，直接调用对应批量接口。
- 复杂筛选的数值区间包含边界；金额单位以 catalog 为准，特别区分元与万元。
- 按成分股反查时，`onlyIncludeFullMatch=Y` 表示同时包含全部输入股票，`N` 表示包含任意一只。
- 指数详情返回内容较多，只抽取问题相关的分类、风险收益、行业、市值风格或跟踪产品信息。
- `eodPriceJson`、`financialIndicatorJson`、`valuationPercentileJson`、`dividendRatioJson` 当前是资源链接，不当作内嵌 JSON 解析。
- 估值倍数和历史分位必须分开：PE 15倍不等于PE分位15%。低分位只描述历史位置，不构成高低估结论或未来收益判断。
- 行情接口选择按此顺序判断：问题要求"现在/实时/盘中"点位、精确行情时间（`date + timeStamp`）、批量刷新行情，或需要涨跌额（`changeValue`）、昨收（`yesterdayClosePrice`）、成交量/额时，直接使用 `quote/index`（批量快照，单次最多 50 只，含精确行情时间；搜索和详情的随附行情字段不含精确行情时间，不能回答实时口径问题）；否则已通过搜索或详情获得随附 `lastPrice`、`changeRate` 时，直接复用随附结果，禁止再调 `quote/index` 获取相同信息。搜索已返回问题所需的表现、估值、基本面、跟踪产品或代表产品字段时，同样直接使用搜索结果，不再调用对应接口重复确认。
- 固定周期年化收益、波动和回撤等指标优先使用详情中的对应字段；需要自定义区间、累计收益或精确起止日期时，再使用区间收益接口。区间收益接口的预设周期为 `1D/1W/1M/3M/6M/1Y`：近3Y/5Y/10Y 等更长周期用详情的固定周期字段（如 `pctChg3Y`）或区间收益接口的 RANGE 自定义区间。
- 用户问题同时涉及"点位/行情、PE/PB 估值、成分股、收益/回撤"等多类指标时，应分别调用对应批量接口补齐数据，禁止用单一接口返回的内容拼凑其他维度。例如同时问"当前点位、PE 和前十大成分股"：搜索或详情的随附 `lastPrice`/`changeRate` 可直接回答点位与涨跌幅，再分别调用 `index/valuation`、`index/holdings` 补齐其余维度；仅当用户另要求涨跌额、昨收或精确行情时间时才追加 `quote/index`。
- 搜索没有返回可用行情，或者用户需要涨跌额、昨收、成交量、精确行情时间、批量行情、分钟轨迹或历史K线时，使用或补充指数行情接口：批量盘口用 `quote/index`，当日分钟轨迹或增量刷新用 `quote/minite`，日/周/月/分钟历史K线用 `quote/index/kline`。
- 指数行情不使用 ETF 专属的 IOPV 或溢折率语义；即使响应出现 `iopv=0`，也不展示为有效指数指标，没有 `deviationRate` 时不补造溢折率。
- `date + timeStamp` 是行情数据时间，`serverTime` 是服务器处理时间。非交易时段应表述为“接口返回的最新一笔行情”，不得把上一交易日行情称为当前实时行情。
- 遇到无数据、代码类型不匹配或历史区间不足时，说明限制并给出可继续查询的方向。

## 调用效率与准确性

1. 在保证准确性的前提下，使用完成回答所需的最少接口，多个代码优先批量查询。
2. 已取得可用数据后，筛选、排序、计算和格式调整都基于已有结果完成，不因此重复调用接口。
   - 如果同一响应需要多次提取、过滤、排序或格式转换，必须先用 `--output` 将响应保存到本地文件，再对该文件执行 `jq`/`python3` 处理；禁止为相同请求再次调用 `api_client.py`。
   - 同一用户问题内的多次 `api_client.py` 调用应使用相同的 `INDEX_HUB_TURN_ID`，否则轮次缓存会失效；只修改输出格式或重试同一请求时不应更换 `TURN_ID`。
   - 示例：
     ```bash
     python3 scripts/api_client.py --method POST --path /skill/v2/index/detail \
       --body '{"fundCodes":["000300"]}' --compact --output /tmp/index_detail.json
     jq -r '.data[] | [.indexCode, .detail.indexName, .detail.indexType] | @tsv' /tmp/index_detail.json
     ```
3. 只有请求失败、数据缺失、结果异常、时效不满足要求，或确实需要其他接口补充关键数据时，才重新或追加调用。
   - 需要强制重新获取同一请求时，给 `api_client.py` 增加 `--refresh`；只修改输出格式时不刷新。
4. 分页按实际需要查询，已经成功取得的页面不重复请求。
5. 必要的补查和重试不算冗余；没有带来新数据或提高准确性的调用属于无效调用。

## Accuracy Rules

- 不凭记忆填写指数名称、分类、成分股、收益、估值、基本面、相关基金或行情；必须来自真实查询结果。
- 数据必须来自 `scripts/api_client.py` 的真实返回；任何绕过 api_client 的方式（自编 HTTP 客户端、直接 import 配置发请求等）获得的数据不得用于回答。
- 代码、字段、单位、日期、分页、批量上限和异常值处理，以 `references/catalog-index.md` 为唯一口径。
- 搜索、详情、成分股反查、持仓、收益、估值、基本面、盘口行情和分钟行情等能力的返回结构可能不同，使用前必须核对 catalog。
- catalog 中的路径一律按 JSON 路径理解，`$` 表示根节点；不要把路径文字误当成真实字段名。
- 如果按 catalog 路径取值失败，或出现字段缺失、`None`、结构与示例不一致、列表异常为空等情况，必须先请求该接口并检查真实返回 JSON 结构，再决定使用哪一层路径；禁止跨接口套用 `data`、`data.list`、`data.data` 模板猜测。
- 金额、收益率、持仓权重、估值倍数、历史分位、基本面比例和日期必须按 catalog 口径换算和展示；行情还必须注明行情日期与时间。
- 不拼接不同时间点的点位、涨跌和成交数据；确需组合时分别注明数据时间。
- 当返回结果为空、状态异常、历史区间不足或字段缺失时，用自然语言说明限制，不补造数据。
- 分批查询时保持每个指数与结果一一对应；多只指数比较时统一日期和指标口径。

## Compliance And Boundaries

- 只提供信息查询、事实比较和风险提示，不提供个性化投资建议、收益承诺或交易指令。
- 用户询问选择、配置、是否购买等问题时，转化为客观维度比较和信息说明。
- 涉及短期表现、实时涨跌、估值分位或市场主题时，提醒其不代表未来收益。
